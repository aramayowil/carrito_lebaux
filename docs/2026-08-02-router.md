# Router: react-router-dom

**Fecha:** 2026-08-02
**Estado:** aplicado

## Instalación

```bash
npm install react-router-dom@latest
```

Quedó fijada `react-router-dom@^7.18.2` (última estable al momento, peer deps
`react >=18` / `react-dom >=18`, compatible con React 19 que ya usa el
proyecto).

## Qué cambió

- `src/routes/router.tsx` — define las rutas con `createBrowserRouter`.
  `RootLayout` es la layout route (Header/Footer fijos); cada página se
  agrega como child route.
- `components/layout/RootLayout.tsx` — pasó de recibir `children` a usar
  `<Outlet />` de react-router, porque ahora es una layout route.
- `app/App.tsx` — ya no arma `RootLayout` + `HomePage` a mano, solo monta
  `<RouterProvider router={router} />`.
- `pages/not-found/NotFoundPage.tsx` — página 404, mapeada a `path: "*"`
  dentro de la layout route.
- `components/layout/Header.tsx` — el logo ahora es un `<Link to="/">` en
  vez de un `<div>`.

## Nota sobre el Button de shadcn

Este proyecto usa la variante de shadcn sobre **Base UI**, no Radix. Base UI
no tiene el prop `asChild` de Radix — el equivalente es `render`:

```tsx
// Radix (NO aplica acá)
<Button asChild><Link to="/">Ir</Link></Button>

// Base UI (lo que usa este proyecto)
<Button render={<Link to="/" />}>Ir</Button>
```

Tenerlo presente para cualquier componente de shadcn que necesite renderizar
como otro elemento (links, etc.) — no copiar ejemplos de la doc de shadcn
que asumen Radix sin revisar antes cuál motor usa `components.json`.

## Cómo agregar una página nueva

1. Crear `src/pages/<nombre>/<Nombre>Page.tsx`.
2. Agregarla como child route en `src/routes/router.tsx`.
3. Si necesita lógica de negocio, esa lógica vive en `features/<feature>`,
   la página solo compone.
